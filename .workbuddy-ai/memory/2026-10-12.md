## shopline_mcp.php → v1.4.0：移除 fields 参数，一律输出完整字段

- 需求：不要用参数控制输出字段，直接输出所有字段。
- 改动（共 13 处，已 grep 确认 `fields` 零残留）：
  1. 删除 6 个工具的 `fields` 入参定义：list_orders、get_order、list_products、get_product、list_customers、get_customer。
  2. 从各工具的 `$allowed` / `cleanQuery()` 白名单中移除 `'fields'`。
  3. `toolGetProduct` / `toolGetCustomer` 删掉 `if (!empty($args['fields'])) {...}` 块，改为直接调接口不带 query。
  4. `formatResult()` 的截断提示由「请用 limit / fields / 时间范围缩小结果」改为「请用 limit / 时间范围 / 筛选条件缩小结果」。
- 未动 `shopline_api_request`：它是通用透传（query 由调用方给），仍可自行传 fields，属设计内的逃生口。
- 版本号 1.3.1 → **1.4.0**。

### 实测（5/5 通过）
- `tools/list`：12 个工具，**无任何工具残留 fields 参数**
- `list_orders`（不传 fields）→ 返回单笔 **92 个字段**（完整）
- `get_order('MG3812')`（不传 fields）→ 92 个字段
- `get_product` / `get_customer` 均正常返回
- `php -l` 无语法错误

### 注意
- 输出体量会显著变大（订单约 92 字段/笔），更依赖 `MAX_OUTPUT_CHARS=50000` 截断保护；批量查询时建议用 `limit` 控制条数。
- 线上是部署副本，需重新上传该文件才生效。

## 新增 shopline_mcp_v2.php —— MCP 协议 2026-07-28（modern / 无状态）

- 需求：v1 保持不动，新建 v2 用最新协议实现同样功能，便于并存灰度。
- **2026-07-28 破坏性变化**（已按新规实现）：
  - 取消 `initialize` / `notifications/initialized` 握手 → 完全无状态；版本随每请求 `_meta["io.modelcontextprotocol/protocolVersion"]` 传。
  - 移除协议方法 `ping` / `logging/setLevel`；移除会话与 `Mcp-Session-Id`；移除 SSE 续传。
  - 新增 `server/discover`（MUST）：返回 `supportedVersions` / `capabilities` / `_meta.serverInfo` / `instructions` / `ttlMs` / `cacheScope`。
  - 版本不支持 → `UnsupportedProtocolVersionError` **-32022**（data: supported/requested）。
  - 所有 result 必须带 `resultType:"complete"`；`tools/list` 必须带 `ttlMs` + `cacheScope`。
  - Streamable HTTP 需带 `Mcp-Method` / `Mcp-Name` / `MCP-Protocol-Version` 头；不一致 → `HeaderMismatch` **-32020**。
  - `structuredContent` 放宽为任意 JSON 值。
- **实现要点**：
  - 头校验用**宽松策略**（头存在才比对），避免误伤未发头的客户端。
  - `tools/call` 返回 `content`（摘要+JSON 文本）+ `structuredContent`（原始数据 + `_page_info` 游标）；后者不受 `MAX_OUTPUT_CHARS` 限制，解决"JSON 被截断无法解析"。
  - 12 个工具函数 + `executeTool` 返回值由 `string` 改为 `['text','data','isError']`。
  - 新增 `okResponse()`（补 resultType + serverInfo）/ `errorResponse()` / `toolError()`。
  - "查不到" 视为空结果（`isError` 不出现，`structuredContent={"orders":[]}`），非错误。
  - 独立令牌 `shopline-mcp-v2-2026-secret-token`，与 v1 隔离。
- **实测 15/15 通过**：discover / tools/list(12 工具+ttlMs) / shopline_ping / get_order(MG3812) / 缺版本→-32022 / 旧版本→-32022 / 头不一致→-32020 / initialize→-32601 / ping→-32601 / 空结果 / 403→isError / 缺参数→isError / `_page_info` 嵌入 / 通知无响应 / **v1 未被改动（仍 2024-11-05 / v1.4.0）**。`php -l` 无语法错误。
- **遗留风险**：modern-only 要求客户端支持 2026-07-28；旧客户端（握手式）会连不上。回退方案=在入口加 legacy 分支（约 10 行）。
- **部署注意**：Nginx 需显式放行 `HTTP_MCP_PROTOCOL_VERSION` / `HTTP_MCP_METHOD` / `HTTP_MCP_NAME`（配置示例已写在 v2 文件头）。

## shopline_mcp.php + awsc_chart_mcp.php 重构到 MCP 协议 2025-11-25

### 2025-11-25 相对 2024-11-05 的实质变化（本次已实现）
1. **版本协商**：`initialize` 时若客户端版本受支持则回同版本，否则回服务端最新版（2025-11-25）。
